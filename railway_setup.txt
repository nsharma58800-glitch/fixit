RAILWAY DEPLOYMENT NOTES

1. Push sell.py, requirements.txt, and Procfile to your GitHub repository.
2. In Railway, deploy the repository as a Worker service.
3. Add a Railway Volume and mount it at: /data
4. Add Railway Variables:
   BOT_TOKEN = NEW token generated with @BotFather (do not use the token shared in chat; revoke it first)
   ADMIN_ID = 6513926862
   FAMPAY_API_KEY = your actual FamPay API key (if using FamPay)
   BHARATPE_API_KEY = your actual BharatPe API key (if using BharatPe)
   RESELLER_API_KEY = your actual reseller API key
5. Redeploy and check Deploy Logs.

IMPORTANT:
- The old bot token was exposed in the uploaded source. Revoke it using @BotFather and use a newly generated token.
- Do not upload .db files containing customer data to a public GitHub repository.
- Existing database data is preserved only if the old DB file is copied into the mounted /data volume before first run, or if the existing Railway volume already contains it.
- Payment gateways will not work until valid API keys are configured.

TESTING NOTE: This configuration is for testing only. Before public/production use, verify payment flows, access controls, database persistence, and API credentials.
